An AI agent that explains failed payments, and proves every claim.

Ask it why a payment failed. It investigates with a read-only Stripe key, answers in plain English, and cites the exact API fields it relied on. A verifier checks every citation against what Stripe actually returned, and an eval suite scores the whole thing.

The eval caught my mistake, not the model's

One case expected the bank to have declined Stripe's "fraudulent" test card. Both models kept answering radar_blocked. They were right: the charge showed outcome.type = blocked and network_status = not_sent_to_network. Radar stopped it before the bank ever saw it. I fixed my test data, not the prompt.

Later, switching to a second model exposed a race condition in my own code: parallel tool calls were getting duplicate evidence IDs, so correct citations were checked against the wrong result. The eval flagged it, and a regression test now covers it.

How it works

  1. Triage. Refunds, card numbers, or anything else outside "explain this payment" are refused before any data is fetched.
  2. Investigate. The agent calls read-only tools: payment intents, charges, customers, payment methods. Results are scoped to one customer and stripped of personal data.
  3. Report and verify. The answer must cite fields like outcome.type = blocked. Each citation is checked against the recorded tool output.
  • Restricted Stripe key that can't write, enforced by Stripe and proven by a startup check that attempts a write.
  • Allowlisted tools, validated IDs, and per-customer scoping on every call.
  • Free text from payments is labeled untrusted, so instructions hidden in it are treated as data.
