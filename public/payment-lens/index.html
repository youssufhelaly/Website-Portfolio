Built for Stripe · Software Engineer Intern, Summer · Toronto

An AI agent that explains failed payments, and proves every claim.

Ask it why a payment failed. It investigates with a read-only Stripe key, answers in plain English, and cites the exact API fields it relied on. A verifier checks every citation against what Stripe actually returned, and an eval suite scores the whole thing.

  1. Triage. Refunds, card numbers, or anything else outside "explain this payment" are refused before any data is fetched.
  2. Investigate. The agent calls read-only tools: payment intents, charges, customers, payment methods. Results are scoped to one customer and stripped of personal data.
  3. Report and verify. The answer must cite fields like outcome.type = blocked. Each citation is checked against the recorded tool output.

Why I built this for Stripe

  • It's built on Stripe's public API: PaymentIntents, Charges, Radar outcomes, and restricted keys.
  • Correctness is measured, not assumed. The eval suite even caught a wrong expectation in my own test data: Radar, not the issuer, had blocked the "fraudulent" test card.
  • Security is part of the design: a least-privilege key enforced by Stripe, allowlisted tools, customer scoping, and handling of prompt injection hidden in payment descriptions.
