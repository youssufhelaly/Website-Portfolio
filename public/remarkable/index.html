Compilers explain why they didn't optimize your code. This agent listens.

remarkable gives an LLM agent clang's optimization remarks, a correctness oracle, and an A/B timing lab. The agent proposes source and flag changes. The lab decides what counts. Every number on this page comes from a recorded run you can replay below.

A reference, not a vibe check
Correctness is the original source at -O0, compared element by element under a contract each workload declares: bit-exact for quantization, a few ulps for compensated summation, float tolerance for the tone curve. It runs at three sizes, including an odd one and n = 3, with guard values after each output. That was added after the agent's first unrolled loops passed at the benchmark size and broke at others.

        
Interleaved A/B timing
Baseline and candidate alternate process launches (AB, BA, AB…) so thermal and scheduler drift hit both arms. Each process runs about 250 ms of repetitions; the statistic is the median of per-process medians.

        
An interval, and a threshold
A 95% percentile bootstrap on the speedup ratio. A change is adopted only if the interval's low end clears 1.03×. Remarks disappearing is a hypothesis, not a result.

        
No winner's curse
Picking the best of several noisy comparisons inflates the number you report. Headline speedups come from a fresh 11-round head-to-head of the final pick vs -O3.

        
Claims must cite the ledger
The agent ends with finish. The harness rejects a recommendation that isn't the lab's current best, or that cites experiments that don't exist, and sends the error back to the model.

        
A fair baseline
Greedy flag search over the same allowlist, same budget, same gates. It wins where a flag is the whole answer (see curve) and stalls where the fix is in the source.

      

      

        
Limits

        
    
          
  • One machine (Apple M4 Pro, Apple clang 21) and four small kernels. These are case studies, not a benchmark suite.
    • 
          
  • macOS exposes no hardware counters to user code, so the lab measures wall time, compile time, and size, not cache misses or IPC.
    • 
          
  • One agent run per workload. LLM sessions are nondeterministic; the traces are what happened, not a distribution.
    • 
          
  • The guard is a policy layer, not a sandbox. For untrusted agents, run the lab in a container.
